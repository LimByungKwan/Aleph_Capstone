# 팀원 테스트 계정 만들기 — 관리자·사장님·순례객 (담당: 지민)

> 기준일: 2026-11-23. 팀원 4명이 각자 **역할별 계정**을 갖고 세 화면을 모두 테스트하는 방법.
> 배포 사이트: https://aleph-capstone.vercel.app (11/23부터 로그인 켜짐)

## 한 줄 요약

**각자 앱에서 계정 2개(본계정 + `+owner` 계정)를 가입한다 → 지민이 Supabase에서 역할을 바꾼다 → 다시 로그인한다.**
관리자는 공용 계정 하나를 돌려 쓰지 않는다. **사장님 역할만 예외로 공용 계정 1개를 같이 쓴다** (11/23 팀 결정, 아래 "사장님 공용 계정").

| 테스트할 역할 | 쓸 계정 | 누가 역할을 바꾸나 |
|---|---|---|
| 관리자 (`admin`) | 본계정 `내이름@gmail.com` | 지민 (SQL) |
| 사장님 (`owner`) | **공용 계정** `jm-demo-owner@example.com` (정류장 분식) — 비밀번호는 지민에게 개인 메시지로 받기 | 이미 지정됨 |
| 순례객 (`pilgrim`) | 로그인 없이 둘러보기 / 필요하면 `내이름+pilgrim@gmail.com` 하나 더 가입 | 바꿀 필요 없음 (가입하면 자동으로 순례객) |

**`+owner` 주소란?** Gmail은 `내이름+아무거나@gmail.com`으로 온 메일도 `내이름@gmail.com` 메일함에 넣어 준다.
그래서 **실제로 쓰는 메일함 하나로** 계정을 여러 개 만들 수 있고, 비밀번호 재설정 메일도 내 메일함으로 온다.
(Gmail·Outlook은 됨. 네이버 메일은 `+`가 안 되니 다른 실제 주소를 쓰기)

## 왜 각자 하나씩인가 (공용 계정을 쓰지 않는 이유)

| | 각자 계정 (이렇게 함) | 공용 계정 1개 |
|---|---|---|
| 누가 바꿨는지 | 감사 로그(`audit_logs`)에 사람별로 남음 | 전부 "관리자 한 명"으로 찍혀서 기록이 의미 없음 |
| 비밀번호 | 본인만 앎 | 카톡 등으로 돌게 됨 |
| 로그인 시도 제한 | 본인만 걸림 | 한 명이 5번 틀리면 4명 모두 15분 잠김 |
| 멀티 접속 이름표 | 각자 닉네임으로 보임 | 4명이 같은 이름 |

## 왜 앱에서 바로 관리자가 될 수 없나

일부러 막아 두었다. 본인이 자기 역할을 바꾸는 것(권한 상승)은 DB 트리거 `guard_profile_update`가 거절한다.
그래서 관리자 지정은 DB 주인 권한이 있는 **Supabase 대시보드(SQL Editor)** 에서만 한다.

## 순서

### 1. 각자: 앱에서 가입 2번 (5분)

1. https://aleph-capstone.vercel.app 오른쪽 위 **로그인 → 회원가입하기**
2. **본계정**: 이메일 `내이름@gmail.com`, 비밀번호(6자 이상), 닉네임 `병관` 처럼
3. 로그아웃 → 다시 **회원가입하기**
4. **사장님 계정**: 이메일 `내이름+owner@gmail.com`, 닉네임 `병관(사장님)` 처럼
   - **이메일은 실제로 받는 메일함**이어야 한다 (비밀번호 재설정 메일을 받으려면 필요)
   - **닉네임**은 멀티 접속에서 머리 위 이름표로 보인다
   - 비밀번호는 다른 사이트와 다르게. 누구에게도 보내지 않는다
   - 가입하면 인증 메일 없이 **바로 로그인**된다 (지금은 이메일 인증을 꺼 둠 — 아래 "이메일 인증" 참고)
5. 가입한 **이메일 주소 2개만** 지민에게 알려 준다 (비밀번호는 알려 주지 않음)

> 첫 가입·로그인이 1분 가까이 걸릴 수 있다. Render 무료 서버가 잠들어 있다가 깨어나는 중이라 정상이다.

### 2. 지민: 관리자로 바꾸기 (Supabase 대시보드)

Supabase → 프로젝트 `scenewalk` → **SQL Editor** 에서 아래를 실행한다. 이메일 4개만 바꾸면 된다.

```sql
-- 관리자 지정 (실행하면 audit_logs에 role_change가 자동으로 남음)
update public.profiles
set role = 'admin'
where id in (
  select id from auth.users
  where email in ('지민@메일', '병관@메일', '혜진@메일', '성근@메일')
);

-- 확인: 4줄이 admin으로 나와야 함
select u.email, p.display_name, p.role
from public.profiles p
join auth.users u on u.id = p.id
where u.email in ('지민@메일', '병관@메일', '혜진@메일', '성근@메일');
```

- `update` 결과가 4행보다 적으면 그 사람이 아직 가입을 안 했거나 이메일 오타

이어서 **사장님 계정**. 사장님은 `role = 'owner'`와 함께 `shop_id`(가게)도 꼭 넣어야 한다 (제약 `owner_has_shop`).
한 가게에 사장님이 여러 명이어도 DB상 문제없다. 기본은 각자 자기 구역 가게로 묶는다:

| 팀원 | 가게 `shop_id` | 가게 이름 |
|---|---|---|
| 병관 | `cafe_soran` | 소란 커피 |
| 혜진 | `shop_hj_snack` | 정류장 분식 (쿠폰 있음 — 시연 4번 가게) |
| 성근 | `shop_sg_bdaycafe` | happy birthday yunseul~!! |
| 지민 | `shop_sg_goods` | SUNGRAY 공식 팝업스토어 (애니 구역엔 가게가 없어서) |

```sql
-- 사장님 지정 (가게와 함께 바꿔야 함)
update public.profiles p
set role = 'owner', shop_id = v.shop_id
from (values
  ('병관+owner@메일', 'cafe_soran'),
  ('혜진+owner@메일', 'shop_hj_snack'),
  ('성근+owner@메일', 'shop_sg_bdaycafe'),
  ('지민+owner@메일', 'shop_sg_goods')
) as v(email, shop_id)
join auth.users u on u.email = v.email
where p.id = u.id;

-- 확인: 본계정 4줄은 admin, +owner 4줄은 owner + 가게
select u.email, p.display_name, p.role, p.shop_id
from public.profiles p
join auth.users u on u.id = p.id
order by p.role, u.email;
```

- 쿠폰 화면까지 보려면 그 가게에 쿠폰(`shop_offers`)이 있어야 한다. 쿠폰이 있는 가게는 `shop_hj_snack`과 애니 구역 명장면 가게 5곳(`shop_jm_*`, 11/25)이다. 명장면 가게에는 아직 사장님 계정이 없어서 쿠폰 발급까지만 되고 사용 처리는 안 된다

### 3. 각자: 새로고침 (안 되면 로그아웃 → 다시 로그인)

11/23부터 페이지를 열 때 서버에서 역할을 다시 받는다(PR #66). 그래서 지민이 역할을 바꾼 뒤 **새로고침**만 하면 된다. 그래도 그대로면 로그아웃 → 다시 로그인. 확인:
- 오른쪽 아래 이름 옆에 **관리자** 표시
- 오른쪽 위 **📊 관리자 화면** 버튼, 주소 `#/admin`
- ⚙ 설정에 계절·시간대·구역 테두리가 보임 (일반 사용자에게는 안 보임)
- `+owner` 계정은 이름 옆에 **사장님** 표시, 자기 가게의 사장님 화면이 열림

## 관리자가 할 수 있는 것 / 없는 것

- 할 수 있음
  - 관리자 화면(`#/admin`) 들어가기 — 단, 서버 모드의 통계 API는 아직 연결 전이라 지금은 "연결 전" 안내가 뜬다 (mock 모드에서는 숫자가 보임)
  - ⚙ 시연용 설정(계절·시간대·구역 테두리)
  - DB 권한상 접속 기록·감사 로그 읽기 (읽는 화면은 아직 없음)
- 할 수 없음: 감사 로그 수정·삭제(관리자도 막힘), 다른 사람 스탬프·쿠폰을 대신 만들기

## 이메일 인증 (지금은 꺼 둠, 11/23 결정)

- 지금 설정: 가입하면 인증 메일 없이 바로 로그인 (Supabase `mailer_autoconfirm: true`)
- 끈 이유: Supabase 무료 기본 메일 발송기는 **우리 Supabase 조직 멤버에게만, 시간당 몇 통**만 보낸다.
  켜 두면 팀원·심사위원이 한꺼번에 가입할 때 인증 메일이 안 가서 시연이 막힐 수 있다
- 그래서 "실제로 받는 메일 주소로 가입"은 **약속(이 문서)으로** 지킨다. 시스템이 막아 주지는 않는다
- 시연 뒤 켜려면: 무료 Gmail SMTP(하루 약 500통)를 Supabase에 연결 → Authentication 설정에서 Confirm email 켜기

## 문제가 생기면

| 증상 | 원인 / 해결 |
|---|---|
| 로그인했는데 관리자 표시가 없음 | 로그아웃 후 다시 로그인. 그래도 없으면 2번의 확인 SQL로 role 확인 |
| "시도가 너무 많아요. N분 뒤에…" | 같은 이메일로 15분에 5번 틀려서 잠김. 안내된 시간만큼 기다리기 |
| 첫 로그인이 1분 가까이 걸림 | Render 무료 서버가 잠들어 있다가 깨어나는 중. 정상 |
| 비밀번호를 잊음 | 지민에게 말하기 (Supabase 대시보드 Authentication → Users 에서 재설정 메일 발송) |

## 사장님 공용 계정 (11/23 결정)

- 이메일: `jm-demo-owner@example.com` / 가게: 정류장 분식(`shop_hj_snack`, 쿠폰 있음)
- 비밀번호: 지민이 관리. **단톡방이 아니라 개인 메시지로** 받는다 (이 문서·레포에는 절대 적지 않는다)
- 주의
  - 같은 이메일로 15분 안에 5번 틀리면 **15분 잠긴다. 공용이라 한 명이 틀리면 모두 못 들어간다** (특히 시연 직전)
  - 쿠폰 사용 기록(감사 로그)은 모두 "정류장 분식 사장님" 한 명으로 남는다
- 비밀번호를 잊으면 지민이 Supabase SQL Editor에서 바꾼다 (`example.com`은 메일을 못 받아서 재설정 메일 불가):

```sql
-- 비용 10을 꼭 적기: gen_salt('bf')만 쓰면 비용 06으로 저장됨 (11/24 빈틈 5)
update auth.users set encrypted_password = crypt('새_비밀번호', gen_salt('bf', 10))
where email = 'jm-demo-owner@example.com' returning email;
```
