# 관리자 계정 만들기 (담당: 지민)

> 기준일: 2026-11-23. 팀원 4명이 각자 관리자 계정을 하나씩 갖는 방법.

## 한 줄 요약

**각자 앱에서 평범하게 가입한다 → 지민이 Supabase에서 역할을 관리자로 바꾼다 → 다시 로그인한다.**
공용 계정 하나를 돌려 쓰지 않는다.

## 왜 각자 하나씩인가 (공용 계정을 쓰지 않는 이유)

| | 각자 계정 (이렇게 함) | 공용 계정 1개 |
|---|---|---|
| 누가 바꿨는지 | 감사 로그(`audit_logs`)에 사람별로 남음 | 전부 "관리자 한 명"으로 찍혀서 기록이 의미 없음 |
| 비밀번호 | 본인만 앎 | 카톡 등으로 돌게 됨 |
| 로그인 시도 제한 | 본인만 걸림 | 한 명이 5번 틀리면 4명 모두 15분 잠김 |
| 멀티 접속 이름표 | 각자 닉네임으로 보임 | 4명이 같은 이름 |

## 왜 앱에서 바로 관리자가 될 수 없나

일부러 막아 두었다. 본인이 자기 역할을 바꾸는 것(권한 상승)은 DB 트리거 `guard_profile_update`가 거절한다.
그래서 관리자 지정은 DB 주인 권한이 있는 **Supabase 대시보드(SQL Editor)** 에서만 한다.

## 순서

### 1. 각자: 앱에서 가입 (2분)

1. 사이트에서 오른쪽 아래 **로그인 → 회원가입하기**
2. 이메일·비밀번호(6자 이상)·닉네임 입력
   - **이메일은 실제로 받을 수 있는 주소**를 쓰자 (나중에 비밀번호 재설정 메일을 받으려면 필요)
   - **닉네임**은 멀티 접속에서 머리 위 이름표로 보인다 (예: `병관`, `혜진`)
   - 비밀번호는 다른 사이트와 다르게. 누구에게도 보내지 않는다
3. 가입한 **이메일 주소만** 지민에게 알려 준다 (비밀번호는 알려 주지 않음)

> 배포 사이트에 아직 로그인 기능이 안 켜져 있으면(Vercel `VITE_API_URL` 미설정) 로컬에서 서버 모드로 가입한다.
> `frontend/.env.local` 에 `VITE_API_URL=https://scenewalk-api.onrender.com` 한 줄을 넣고 `npm run dev` (주소 `http://localhost:5173`).
> Render 환경변수 `ALLOWED_ORIGINS`에 `http://localhost:5173`이 있어야 접속된다. 안 되면 지민에게 말하기.

### 2. 지민: 관리자로 바꾸기 (Supabase 대시보드)

Supabase → 프로젝트 `scenewalk` → **SQL Editor** 에서 아래를 실행한다. 이메일 4개만 바꾸면 된다.

```sql
-- 관리자 지정 (실행하면 audit_logs에 role_change가 자동으로 남음)
update public.profiles
set role = 'admin'
where id in (
  select id from auth.users
  where email in ('지민@메일', '병관@메일', '혜진@메일', '성근@메일')
);

-- 확인: 4줄이 admin으로 나와야 함
select u.email, p.display_name, p.role
from public.profiles p
join auth.users u on u.id = p.id
where u.email in ('지민@메일', '병관@메일', '혜진@메일', '성근@메일');
```

- `update` 결과가 4행보다 적으면 그 사람이 아직 가입을 안 했거나 이메일 오타
- 사장님 계정(`owner`)은 다르다. `role = 'owner'`와 함께 `shop_id`도 넣어야 한다 (제약 `owner_has_shop`)

### 3. 각자: 로그아웃 → 다시 로그인

역할은 로그인할 때 받아 오므로 한 번 다시 로그인해야 바뀐다. 확인:
- 오른쪽 아래 이름 옆에 **관리자** 표시
- 오른쪽 위 **📊 관리자 화면** 버튼, 주소 `#/admin`
- ⚙ 설정에 계절·시간대·구역 테두리가 보임 (일반 사용자에게는 안 보임)

## 관리자가 할 수 있는 것 / 없는 것

- 할 수 있음
  - 관리자 화면(`#/admin`) 들어가기 — 단, 서버 모드의 통계 API는 아직 연결 전이라 지금은 "연결 전" 안내가 뜬다 (mock 모드에서는 숫자가 보임)
  - ⚙ 시연용 설정(계절·시간대·구역 테두리)
  - DB 권한상 접속 기록·감사 로그 읽기 (읽는 화면은 아직 없음)
- 할 수 없음: 감사 로그 수정·삭제(관리자도 막힘), 다른 사람 스탬프·쿠폰을 대신 만들기

## 끝나고 정리

- 캡스톤이 끝나면 관리자 권한을 거둔다 (계정은 남기고 역할만 되돌림):

```sql
update public.profiles set role = 'pilgrim'
where id in (select id from auth.users where email in ('병관@메일', '혜진@메일', '성근@메일'));
```

- 테스트 계정 `jm-test-pilgrim`, `jm-test-ui` 는 11/30 리허설 뒤 삭제 예정. 시연용 사장님 계정(`jm-demo-owner`)은 지우지 않는다.

## 문제가 생기면

| 증상 | 원인 / 해결 |
|---|---|
| 로그인했는데 관리자 표시가 없음 | 로그아웃 후 다시 로그인. 그래도 없으면 2번의 확인 SQL로 role 확인 |
| "시도가 너무 많아요. N분 뒤에…" | 같은 이메일로 15분에 5번 틀려서 잠김. 안내된 시간만큼 기다리기 |
| 첫 로그인이 1분 가까이 걸림 | Render 무료 서버가 잠들어 있다가 깨어나는 중. 정상 |
| 비밀번호를 잊음 | 지민에게 말하기 (Supabase 대시보드 Authentication → Users 에서 재설정 메일 발송) |
