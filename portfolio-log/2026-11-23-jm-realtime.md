# 2026-11-23 · 멀티 접속(WebSocket) 서버

- 날짜: 2026-11-23
- 프로젝트: SceneWalk AI (캡스톤)
- 도구: Node.js 22, Express 5, ws 8, React Three Fiber, Render(무료), Claude Code
- 목표: 같은 3D 맵에 여러 사람이 동시에 들어와 서로의 캐릭터가 보이게 한다. 무료 서버 한 대(512MB, 포트 1개)로 버티게 설계한다.

## A. AI가 한 일
- 실시간 채널 설계·구현: 기존 API 서버와 같은 포트에 WebSocket(`/realtime`)을 붙임 — 증거: `server/src/realtime.js`, `server/src/index.js`
  - 위치는 DB에 저장하지 않고 메모리에만 둠 (1초에 여러 번 바뀌는 값을 DB에 쓰면 무료 DB가 버티지 못함)
  - 받은 위치를 바로 뿌리지 않고 0.1초마다 모아서 한 번에 보냄(10Hz 배치) → 메시지 수가 "사람 수 × 프레임 수"로 늘지 않음
- 방어 장치(테스트로 확인) — 증거: `server/test/realtime.test.js` (5개, 서버 전체 41개 통과)
  - 등록된 화면 주소(Origin)만 접속 허용, 다른 사이트는 403
  - 정원(기본 50명) 초과 시 503, 메시지 1KB 제한, 초당 40개 넘게 보내면 끊음(1008)
  - 접속 후 10초 안에 인사(hello)가 없으면 끊음, 30초마다 ping으로 죽은 연결 정리
  - 이름은 화면이 보낸 값이 아니라 로그인 토큰으로 서버가 DB에서 읽음 → 위장 불가. 위조 토큰은 손님 처리
  - 좌표·속도 범위 검사, 깨진 JSON 무시, 다른 사람에게는 이름·캐릭터·위치만 전달(이메일·역할·DB id 제외)
  - 토큰은 주소(`?token=`)가 아니라 첫 메시지로 보냄 → 접속 기록(로그)에 토큰이 남지 않음
- 화면: 내 위치 보내기 + 다른 사람 그리기(보간으로 부드럽게, 순간이동은 즉시 이동), 끊기면 1→2→4…30초 간격 재연결 — 증거: `frontend/src/game/multiplayer/`
- 확인: 로컬 서버 + 브라우저 1개 + 가짜 접속자(Node 스크립트)로 다른 캐릭터가 이름표와 함께 걷는 것 확인

## 결과와 배운 점
- 결과: 무료 서버 한 대에서 위치 동기화가 되는 v1. 서로 통과 가능(충돌 없음), 맵 하나에 한 방
- 배운 점
  - 실시간 기능의 비용은 "메시지 수"에서 나온다. 모아서 보내기(배치)와 변화가 있을 때만 보내기로 줄인다
  - WebSocket은 CORS가 적용되지 않아서 Origin 검사를 서버가 직접 해야 한다
  - 남은 위험: Render 무료 서버가 잠들어 있으면 첫 접속이 50초쯤 걸림, 서버 한 대라 재시작하면 모두 재연결
- 면접 대비 한 줄: 「位置情報はDBに保存せずメモリで管理し、100msごとにまとめて配信することで、無料サーバー1台でも負荷を抑えました。」
