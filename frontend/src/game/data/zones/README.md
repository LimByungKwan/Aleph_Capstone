# 구역(zone) 작업 안내

맵은 **중앙 광장(HUB)** 하나와 **구역 4개**로 나뉘어 있어요.
구역 하나 = 이 폴더의 JSON 파일 하나예요.

```
              [ JM 애니메이션 ]
                     |
[ SG K-POP ] —— [ HUB 중앙 광장 ] —— [ BK 데이트 코스 ]
                     |
              [ HJ 영화·드라마 ]
```

| 파일 | 구역 | 담당 | 대표색 | 위치 | 중심(origin) |
|---|---|---|---|---|---|
| `jm_anime.json` | 애니메이션 | 지민 (JM) | 하늘 | 북쪽 | (0, -85) |
| `bk_date.json` | 데이트 코스 + 언덕 | 병관 (BK) | 분홍 | 동쪽 (+ 그 북쪽 언덕) | (85, -40) ※ 80 × 160 |
| `hj_drama.json` | 영화·드라마 | 혜진 (HJ) | 주황 | 남쪽 | (0, 85) |
| `sg_kpop.json` | K-POP | 성근 (SG) | 보라 | 서쪽 | (-85, 0) |

중앙 광장은 50 × 50m, 구역은 하나에 **80 × 80m**예요. (BK만 북쪽 언덕까지 포함해 80 × 160m — x -40 ~ 40, z -80 ~ 80) 광장과 구역 사이는 폭 6m 길로 이어져 있어요.

---

## 꼭 지킬 규칙

1. **내 구역 파일만 수정해요.** `../hub.json`(중앙 광장)과 **다른 사람 구역 파일은 수정 금지**예요.
   고치면 GitHub에서 합칠 때 충돌이 나요. 광장을 바꿔야 하면 팀에 먼저 말해 주세요.
2. **1 = 1m** 예요. 캐릭터 키가 약 1.6m예요.
3. **좌표는 내 구역 한가운데가 (0, 0)** 이에요. `origin` 기준 상대 좌표라서,
   `origin`만 바꾸면 구역 전체가 통째로 움직여요.
4. **구역 크기(80 × 80m) 안에서만** 배치해요. → x, z 모두 **-40 ~ 40** 사이
   (건물은 가운데 좌표 ± 크기의 절반까지 차지해요. 예: 가로 8m 건물을 x = 38에 두면 34~42 → 밖으로 나감 ❌)
5. **건물 높이는 6 ~ 12m** 로 해요.
6. **GLB 모델은 파일당 5MB 이하**로, `frontend/public/models/` 폴더에 넣어요.
7. **실제 작품·배우·아이돌의 이름, 사진, 로고는 쓰지 않아요.** 작품명, 가게 이름, 간판, 인물은 모두 가상으로 만들어요.
   (예: ❌ 실제 드라마 제목, 실제 그룹명 / ⭕ 「여름이 머무는 정류장」, 「골목 끝의 빛」 같은 지어낸 이름)
8. 길 입구(광장 길이 내 구역에 들어오는 곳)는 막지 않아요.

| 구역 | 입구 위치 (내 구역 좌표) | 비워 둘 곳 |
|---|---|---|
| JM | (0, 40) 남쪽 가운데 | x -5 ~ 5, z 20 ~ 40 |
| BK | (-40, 40) 서쪽 (남쪽 절반의 가운데) | x -40 ~ -30, z 35 ~ 45 |
| HJ | (0, -40) 북쪽 가운데 | x -5 ~ 5, z -40 ~ -15 |
| SG | (40, 0) 동쪽 가운데 | x 20 ~ 40, z -5 ~ 5 |

방향: **북쪽 = z가 마이너스(-)**, 남쪽 = z 플러스(+), 동쪽 = x 플러스(+), 서쪽 = x 마이너스(-).

## 파일 구조

(`//` 설명은 이해를 돕기 위한 것이고, 실제 JSON 파일에는 쓰면 안 돼요.)

```jsonc
{
  "zoneId": "SG",            // 구역 코드 (바꾸지 않기)
  "owner": "성근",
  "name": "K-POP",           // 화면에 보이는 구역 이름
  "origin": [-85, 0],        // 구역 한가운데의 맵 좌표 (바꾸지 않기)
  "size": [80, 80],
  "color": "#b18cff",        // 구역 대표색
  "colorName": "보라",
  "entrance": { "position": [40, 0], "rotationDeg": 90, "width": 6 },
  "roads": [],               // 길·보도·광장 바닥 (충돌 없음)
  "markings": [],            // 횡단보도·차선·도로 글씨 (선택)
  "buildings": [],           // 건물
  "props": []                // 나무·가로등·벤치 같은 소품
}
```

## 건물 1개 추가하기

`buildings` 목록에 한 줄 추가해요. (앞 줄 끝에 쉼표 `,` 잊지 않기!)

```json
{ "id": "my_stage", "style": "modern", "position": [-10, -20], "size": [12, 9, 10], "rotationDeg": 0, "color": "#e9d5ff", "model": null,
  "signs": [{ "text": "별빛 연습실", "bg": "#f5f3ff", "fg": "#6d28d9", "awning": "#7c3aed" }] }
```

| 항목 | 뜻 |
|---|---|
| `id` | 내 구역 안에서 겹치지 않는 이름 |
| `position` | [x, z] 건물 바닥 한가운데 (내 구역 좌표) |
| `size` | [가로, 높이, 깊이] (m) |
| `rotationDeg` | 회전(도). 건물 앞면은 기본이 **남쪽(+z)**. 0 = 남쪽, 180 = 북쪽, 90 = 동쪽, -90 = 서쪽을 바라봄 |
| `style` | 겉모습: `"hanok"`, `"modern"`, `"cafe"`, `"mural"`, 없으면 회색 박스 |
| `model` | GLB 경로. 예: `"/models/my_stage.glb"` → style보다 우선 |
| `signs` | 간판 (modern, cafe) |

소품 `style`: `"tree"`, `"lamp"`, `"bench"`, `"bins"`, `"pavilion"`, `"busShelter"`, `"signPost"`, `"fence"`, `"vending"`, `"stoneWall"`

BK 구역에서 만든 스타일도 누구나 쓸 수 있어요 (`bk_date.json`에 사용 예시가 있어요):
- 건물: `"hanokShop"`(줄무늬 차양 한옥 가게, `"awning"` 색 / `"display": "cake" | "flower"` / `"roofProp": "camera"`),
  `"hanokCafe"`, `"rooftopRestaurant"`, `"neonWings"`(빛나는 날개 벽), `"observationTower"`(전망 타워)
- 소품: `"cherryTree"`, `"lanternLamp"`, `"fountain"`, `"roundPlaza"`, `"lockFence"`, `"telescope"`, `"bollard"`, `"flowerBed"`, `"rock"`, `"terrace"`

### 언덕·데크 산책로 (선택)

구역 파일에 `"terrain"` 목록을 넣으면 언덕과 나무 데크 산책로를 만들 수 있어요. 충돌도 자동으로 생겨요.

```json
"terrain": [
  { "type": "hill", "id": "hill", "center": [-25, -26], "radius": [13, 12], "height": 6, "plateau": 0.5 },
  { "type": "deck", "id": "walk", "width": 2.4, "points": [[-12, -11, 0.1], [-32, -11, 2], [-32, -15, 2]] }
]
```
- `hill`: 가운데 `center`, 가로·세로 반지름 `radius`, 높이 `height`, 꼭대기 평평한 비율 `plateau`
- `deck`: `points`의 각 점은 [x, z, 높이]. 점을 이어 경사로와 꺾이는 곳을 만들어요 (꺾을 때는 가로·세로로만, 경사는 완만하게)
- `stairs`: `{ "type": "stairs", "id": "s1", "from": [x, z, 높이], "to": [x, z, 높이], "width": 4 }` — 계단 (충돌은 매끄러운 경사로)
- `tower`: `{ "type": "tower", "id": "t1", "position": [x, z], "rotationDeg": 0 }` — 들어갈 수 있는 전망 타워
  (1층 홀 반지름 6m, 문은 rotationDeg 방향, 가운데 엘리베이터 발판에 서 있으면 전망대(18m)까지 자동으로 오르내림)
- 언덕 위에 건물·소품을 올리려면 그 항목에 `"onTerrain": true` → 언덕 높이만큼 자동으로 올라가요
  (`"elevation": 18`을 같이 쓰면 그 위로 더 올림 — 예: 전망대 안 망원경)

충돌 박스는 `size` 그대로 자동으로 생겨요. 따로 정하고 싶으면:
- `"collider": [0.5, 3, 0.5]` → 그 크기로 (예: 나무는 줄기만)
- `"collider": false` → 충돌 없음 (예: 안으로 들어가는 정자)

## 상호작용 지점 1개 추가하기

상호작용 지점(촬영지·카페·NPC)은 팀 공용 파일 **`shared/places.json`** 에 있어요.
⚠ 여기는 **맵 전체 기준 절대 좌표**예요. → 내 구역 좌표 + origin

예: SG 구역(origin = [-85, 0]) 안의 (-10, -14) 위치 → 절대 좌표 x = -85 + (-10) = **-95**, z = 0 + (-14) = **-14**

```json
{
  "id": "spot_sg_stage",
  "type": "spot",
  "zone": "SG",
  "name": "데뷔 무대 앞",
  "work": "가상 그룹 「스텔라라인」 뮤직비디오",
  "description": "가상 아이돌 그룹이 첫 뮤직비디오를 찍은 연습실 앞.",
  "tags": ["K-POP", "뮤직비디오"],
  "position": [-95, 0, -14],
  "radius": 2.5,
  "model": null
}
```

- `type`: `"spot"`(촬영지) / `"cafe"`(카페) / `"npc"`(NPC)
- `zone`: `"JM"` / `"BK"` / `"HJ"` / `"SG"` / `"HUB"` ← **내 구역 코드를 꼭 적기**
- `position`: [x, y, z] — 가운데 y는 높이(보통 0)
- `radius`: 이 거리(m) 안에 들어오면 감지 → E 키로 열기
- places.json은 넷이 같이 쓰는 파일이라, 내 구역 지점만 추가·수정하고 수정 전에 팀에 한마디 해 주세요.

## 테스트 방법

1. 터미널에서:
   ```bash
   cd frontend
   npm run dev
   ```
2. 브라우저에서 `http://localhost:5173` 열기
3. 위에서 내 구역이 대표색 사각형 안에 잘 들어갔는지 확인
4. **"▶ 3인칭으로 플레이하기"** → 광장에서 내 구역 입구 아치까지 걸어가서
   - 건물에 부딪히는지 (뚫고 지나가면 size 확인)
   - 길이 막히지 않았는지
   - 상호작용 지점에서 왼쪽 위 `nearbyPlaceId`가 바뀌고, E 키로 `openPanel`이 열리는지 (ESC로 닫기)
5. 브라우저 개발자 도구(F12) → Console 탭에 빨간 에러가 없는지

도움이 되는 스위치 (`frontend/src/game/config.js`, 확인용으로만 바꾸고 커밋하지 않기):
- `SHOW_GRID = true` → 1m 격자
- `PHYSICS_DEBUG = true` → 충돌 박스를 선으로 보기
- `SHOW_ZONE_OWNERS = false` → 발표용 (담당자 코드 숨김)
